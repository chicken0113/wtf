# Everything Grows — 게임 기본 틀

## 중심 경험
세상과 화면의 일부를 뜯어내 심는다. 원래 역할을 닮은 새 존재나 생산원으로 자라는 모습을 발견하고, 그것을 다음 농사에 활용한다.
기존 what-the-farm과 별개의 게임이다. 기존 코드·에셋·전투·경제·스테이지 진행을 전제로 하지 않는다.

## 확정된 방향
- 탑뷰. 첫 시제품은 Unity 2D; 최종 2D/2.5D 및 미술 스타일은 보류.
- 물건, 배경, UI가 농사의 재료가 된다. 원래 자리에서 실제로 사라지고 그 기능도 변한다.
- 뜯기 능력은 처음부터 있다. 진행은 권한 해금보다 플레이어가 가능한 행동을 발견하는 과정이다.
- 물건 자체가 자라 새로운 행동을 얻는 결과와 물건을 생산하는 식물로 자라는 결과를 함께 사용한다.
- 물건은 심기 전에도 쓸 수 있다. 심기는 새 기능에 투자하는 선택이다.

## 기본 순환
관찰 → 뜯어내기/획득 → 지금 사용하거나 심기 → 돌보기 → 변화 발견 → 수확/새 기능 활용 → 새로운 실험.
농사를 중심에 둔다. 농장의 배치와 돌봄이 결과를 만들며, 단순 대기나 무작위 보상으로만 끝내지 않는다.

## 결과를 만드는 규칙
1. 결과가 원래 대상의 역할과 연결돼 추측 가능해야 한다.
2. 심기 전에 하던 일과 성장 뒤 하는 일이 달라야 한다.
3. 화면과 기능에 빈자리가 남는다. 획득만 하고 아무 비용도 없는 복사는 사용하지 않는다.
4. 같은 뜯기 조작을 세계·배경·UI에서 사용한다. 항상 실험을 취소/복구할 수 있는 경로를 준비한다.
5. 필수 조작은 고정한다. 마지막 보관 칸과 이동/메뉴 입력은 없애지 않는다.
6. 재료를 잃거나 농장을 망쳐도 진행 복구가 가능해야 한다. 복구 방식과 예외는 앞으로 구체화한다.

## 첫 장소와 발견 순서
작은 농장과 주변 공간에서 시작한다. 주변 도구 → 시설/배경 → UI까지 실험 범위를 넓히도록 상황을 설계한다.
이미 알아차린 플레이어는 처음부터 구름·UI를 뜯을 수 있다. NPC의 직접적인 정답 설명보다 필요와 일관된 반응으로 유도한다.
정해진 엔딩은 두지 않는다. 직접 전투를 기본 농사와 함께 구현하고, 심을 수 있는 대상을 이후 확장한다. 제작·조립·빌딩 시스템은 넣지 않는다. 경영과 탐험을 추가 콘텐츠의 중심으로 잡지 않는다. 전체 월드 규모, 장기 목표, 스토리, 멀티플레이, 실패/시간 제한은 아직 정하지 않는다.

## 첫 시제품의 다섯 사례
| 대상 | 뜯은 뒤의 비용 | 원래 사용 | 심고 성장한 결과 |
|---|---|---|---|
| 삽 | 바닥의 삽이 사라짐 | 직접 경작 | 주변 땅을 파는 살아 있는 삽 |
| 물뿌리개 | 바닥의 물뿌리개가 사라짐 | 직접 물주기 | 주변 밭에 물을 주는 식물 |
| 돌 | 주변 돌이 사라짐 | 농사 재료 | 돌을 생산하는 식물 |
| 구름 | 배경의 구름이 사라짐 | 배경의 일부 | 넓은 범위에 물을 주는 비구름 |
| 인벤토리 칸 | 실제 보관 용량 1 감소 | 물건 보관 | 추가 보관 공간을 제공하는 창고 식물 |

원래 자리를 보여 주는 흔적만 남겨 뜯었다는 사실을 읽을 수 있게 한다. 마지막 보관 칸은 유지한다.
모든 대상의 구현을 약속하는 목록이 아니라 핵심 규칙을 확인할 작은 범위다.

## 개발 순서
1. 새 프로젝트, 데이터 구조, 탑뷰 이동, 공통 뜯기/획득 및 심기.
2. 물주기와 성장, 위 다섯 결과, 실제 UI 용량 변화.
3. 발견을 유도하는 짧은 첫 장소. 재료 회수와 실패 복구 보강.
4. 플레이 확인 후 재미있는 상호작용을 확장하고 장기 목표 결정.
5. 미술 방향 확정, 연출과 사운드 제작.

## 첫 검증 질문
새 물건을 보면 심어 보고 싶은가? 결과의 연결을 이해하는가? 뜯어서 생기는 빈자리가 선택에 영향을 주는가?
평범한 물건에서 배운 조작을 UI·배경에 스스로 시도하는가? 농장에 생긴 기능이 다음 실험에 도움이 되는가?

## 현재 개발 단계
작업 위치는 C:/Users/MSI/wtf, 원격은 chicken0113/wtf이다. 첫 단계는 픽셀 탑뷰 2D 시제품에서 뜯기·경작·식재·물주기·성장·회수를 확인한다. 마우스가 가리킨 칸은 가능하면 초록색, 불가능하면 빨간색으로 표시한다. 성장 대기 중에는 물 필요 여부와 진행 막대를 표시한다. 자동 경작/물주기/생산/창고 효과는 기존 시제품의 임시 검증용 결과이며 최종 콘텐츠로 확정하지 않는다.

현재 그래픽 단계는 따뜻한 픽셀 탑뷰, 방향별 캐릭터, 도구 사용 연출, 아이콘 핫바로 기본 농사 조작을 읽기 쉽게 만드는 범위다. E로 식재와 수확을 처리하고 좌클릭은 도구·무기 사용에 쓴다. 일자·계절·상점·주민 등 장기 시스템은 추가하지 않았다.

## 현재 확정한 농사 + 전투 틀

- 농장과 전투 구역을 하나의 연속된 오픈필드로 연결한다. 선택형 전투 입장, 별도 전투 씬, 강제 습격을 기본 진행으로 사용하지 않는다.
- 플레이어는 준비한 뒤 걸어서 싸우러 나가며, 적을 피하거나 농장으로 돌아올 수 있다.
- 첫 필드는 중앙의 안전한 농사 구역과 바깥의 적 출현 구역으로 구성한다. 바깥에서도 심기는 가능하다.
- 자유 이동, 마우스 방향 공격, 회피, 공격 예고를 사용한다. 격자는 경작·식재에만 사용한다.
- 기본 농사와 전투의 연결을 먼저 만든 뒤 심을 수 있는 대상을 확장한다. 분위기는 B급의 황당한 변화로 잡는다.
- 변화 완료 대상의 추가 변환은 없다. 기본 수확은 결과물을 가져가고 밭을 비우는 방식이다.
- 씨앗→일반 작물 재배와 작물→특수 변화는 구분한다. 이 씨앗 흐름은 현재 아직 구현하지 않았다.
- 죽은 플레이어/NPC를 심어 부활시키는 규칙은 기획으로 유지하며 변경 가능하다. 현재 솔로 테스트의 자동 농장 복귀는 임시 복구 수단이다.

### 첫 전투 시제품

검→엑스칼리버, 활→총의 두 성장 결과를 구현한다. 물을 주면 기본 8초 뒤 성숙하며 수확해서 사용한다.
추격형 적과 원거리 적을 배치한다. 적의 원거리 공격은 예고 시 조준한 방향으로 날아가고, 플레이어가 움직이거나 회피해 피할 수 있다.
처치한 적은 다음 식재에 사용할 검/활을 떨어뜨린다. 새로운 적 재료와 개별 특수 결과는 이후 확장할 대상이다.
기존 다섯 사례의 자동화 동작은 초기 검증용으로 남아 있으며 새 기획의 최종 결과가 아니다.

## 맵 저작 방식
맵은 Unity 씬의 EditableMap에서 직접 배치한다. 바닥, 길, 장식, 아이템, 적 출현 지점, 안전 영역, 월드 경계, 플레이어 시작 위치를 수정할 수 있다. 실행 때 배치를 초기화하지 않는다. 실제 경작 가능 영역은 경작 가능한 바닥과 월드 경계가 함께 결정한다. 이것은 개발용 씬 편집 기능이며 게임 내 빌딩 시스템이 아니다.

## 초기 농장과 상점 시제품

집 한 채와 5×3 경작지, 집 옆 상인으로 초기 화면을 구성한다. 기존 테스트용 길과 바닥 아이템은 비활성화해서 보관한다.
상인에게 가까이 가서 E로 상점을 열고, 구매 버튼으로 아이템을 얻고, 인벤토리 우클릭으로 판매한다. 상점이 열린 동안 우클릭은 UI 칸 뜯기를 수행하지 않는다.
NPC별 ID, 판매 목록, 구매가·판매가를 NpcManager에서 직접 설정한다. 상점 목록에 없는 아이템도 아이템 기본 판매가로 판매할 수 있다.
기본 시작 골드는 100, 재고는 무제한이다. 이는 농사 재료를 얻고 수확물을 활용할 기본 상점이며 경영 시스템을 중심 콘텐츠로 확정한 것은 아니다.
집 내부, NPC 이동·대사·부활은 이번 단계에 포함하지 않는다.

## 기본 작물 농사 규칙

괭이로 경작하고, 씨앗을 심고, 물을 주면 초 단위로 성장한 뒤 수확한다. 맨손 경작·물주기는 사용하지 않는다.
심기/수확은 E키, 도구 사용은 좌클릭이다. 같은 씨앗·작물은 인벤토리에서 수량으로 쌓이며 심기/판매는 한 개씩 처리한다.
작물별 Growth Seconds로 성장 시간을 설정한다. Regrow Seconds가 0보다 크면 수확 후 식물이 남으며 다시 물을 줬을 때 해당 시간 동안 재성장한다.
날짜·계절·잠자기·에너지는 사용하지 않는다. 물은 성장 중 자동으로 마르지 않는다. 작물 품질·비료·날씨 등은 이후 단계다. 기존 특수 물건도 초 단위로 성장한다.
