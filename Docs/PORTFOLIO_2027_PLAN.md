## 작품의 중심 주장

《Everything Grows》는 게임 속 대상을 무엇이든 심어 볼 수 있는 2D 탑뷰 생존·농사 게임이다. 작물뿐 아니라 도구, 주변 사물, 화면의 일부도 심기 대상이 된다. 플레이어는 새로운 대상을 발견할 때마다 심을 수 있는지 시험하고, 기른 것을 먹거나 사용하거나 팔거나 다시 심어 다음 활동에 활용한다.

심기의 중심은 플레이 중 보이는 무엇이든 심을 수 있다는 범위다. 심은 뒤의 결과를 모든 대상에 하나의 형태로 고정하지 않는다. 당근 자체를 심어 다시 당근을 얻는 방식은 가능하지만 모든 대상에 적용할 기본 산출 규칙은 아니다. 구체적 결과는 게임 기획을 진행하며 정한다.

## 현재 합의한 기획

- 핵심 경험: 평소 심을 수 없다고 생각한 대상에도 심기를 시도하고, 같은 규칙이 어디까지 적용되는지 발견한다.
- 생존과 농사의 관계: 농사로 식량과 판매할 물건을 마련해 다음 탐험을 준비한다.
- 월드 방향: 하나의 연속된 필드에서 자유롭게 거점을 잡는 방향으로 논의했다. 기존 농장·마을·탑 씬은 이전 구조의 흔적이므로 최종 월드 구성으로 설명하지 않는다.
- 시간 방향: 일반 몬스터는 낮에 활동하고 밤에는 상인을 이용한다. 세부 난도와 생활 주기는 추가 검토한다.
- 전투 방향: 이동·조준·회피의 손맛을 갖춘 탑뷰 액션. 포트폴리오에서는 농사와 전투가 연결되는 이유를 먼저 설명한다.
- 세계관: 생물과 물건이 식물에서 갈라져 나온 세계라는 설정을 사용한다. 포트폴리오에서는 심기 규칙을 이해시키는 데 필요한 만큼만 보여준다.

## 포트폴리오에서 증명할 것

1. **무엇을 심을 수 있는가:** 작물에서 시작해 도구·주변 사물·UI로 범위를 넓혀 보여준다. 예시는 실제 구현과 기획안을 구분해 표기한다.
2. **심은 뒤 무엇을 얻는가:** 심은 대상과 성장 결과의 관계를 사례로 보여준다. 사례와 결과는 게임 기획을 먼저 진행하며 정한다.
3. **왜 반복해서 심는가:** 식량, 판매, 재식재, 다음 탐험 준비가 실제 플레이 선택으로 연결되는지 설명한다.
4. **기획을 어떻게 검증했는가:** 현재 시제품에서 확인된 조작·농사·전투·월드 기능과 아직 기획 단계인 콘텐츠를 분리한다. 화면 자료와 테스트 결과는 확보한 것만 싣는다.
5. **왜 방향을 수정했는가:** 당근→다른 물건처럼 변화 중심으로 기획했을 때 생긴 문제와, 무엇이든 심기 중심으로 바꾼 판단을 짧고 구체적으로 설명한다.

## 나중에 검토할 페이지 구성 초안

| 구간 | 페이지의 역할 | 필요한 자료 |
| --- | --- | --- |
| 표지·요약 | 작품과 기획자의 핵심 주장을 한눈에 전달 | 제목, 대표 화면 또는 도식 |
| 핵심 규칙 | 무엇이든 심을 수 있다는 범위를 설명 | 심기 대상의 사례와 플레이 흐름 |
| 첫 플레이 예시 | 무엇이든 심는 규칙을 처음 이해하는 과정을 보여줌 | 사례와 장면은 기획 후 선정 |
| 확장 사례 | 도구·환경·UI의 심기를 검토 | 대상별 구체 규칙 결정 필요 |
| 생존 루프 | 재배, 식량, 판매, 탐험, 전투의 연결 | 한 번의 플레이 흐름 |
| 제작·검증 | 구현 현황, 기획 수정 과정, 검증 질문 | 시제품 화면·테스트 기록 |

쪽 수는 세부 기획과 확보한 증거를 보고 결정한다. 페이지를 채우기 위해 미확정 시스템을 확정된 것처럼 쓰지 않는다.

## 다음에 결정할 기획 질문

1. 도구·주변 사물·UI에도 심기를 시도할 수 있다는 사실을 플레이어가 어떻게 발견하는가.
2. 체력 하트와 인벤토리 칸을 심을 때 원래 위치에서 무엇이 빠지고, 수확 후 무엇이 늘어나는가.
3. 심은 결과를 식량·판매·재식재·탐험 준비에 어떻게 활용하는가.
4. 처음 본 대상에 심기를 시도하도록 플레이어에게 어떤 신호를 줄 것인가.

대상별 수확량과 경제 수치는 플레이 테스트 후 조절할 밸런스 항목이다. 포트폴리오 본문에서 지금 확정할 기획 규칙으로 다루지 않는다.

## 기획과 구현의 구분

현재 프로젝트의 게임 코드와 씬은 여러 차례 기획 변경을 거친 시제품이다. 이전의 특수 변환 결과, 안전 농장·층별 탑, 농장·마을 연결 구조가 남아 있다. 포트폴리오 작성 시 최신 기획으로 확정된 내용과 현재 동작하는 기능을 각 페이지에서 구분한다. 최신 심기 방향은 GAME_DESIGN.md와 PLANNING_BACKLOG.md를 따른다.
