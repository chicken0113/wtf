# 길드 의뢰와 전체 동선 점검

## 플레이 흐름

1. 마을 길드로 들어가 접수원 또는 왼쪽 게시판 가까이에서 E.
2. 의뢰의 Accept로 수락.
3. 던전 입구 필드를 통해 CombatTest로 이동해 몬스터 처치.
4. 길드에 돌아와 같은 화면의 Claim reward로 골드 수령.

기본 의뢰는 던전 몬스터 2마리 처치/50골드(반복 가능), 원거리 몬스터 1마리 처치/40골드(1회)다. 임시 검증용 수치이며 아래에서 조절한다. 여러 의뢰를 동시에 수락할 수 있고 조건에 맞는 처치 하나가 각 의뢰에 반영된다.

수락 이후 처치만 집계한다. 훈련 표적은 제외한다. 완료만으로 골드가 지급되지 않고 길드에서 보고해야 한다. 반복 의뢰도 재수락해야 새 처치가 집계된다. 메뉴는 기존 인벤토리·대화와 동일하게 싱글플레이 시간을 멈추고 E/Esc/Close로 닫힌다.

## Unity 설정

`Tools > Everything Grows > Guild quests`로 `Assets/Resources/GuildQuests.asset`을 선택해 Inspector에서 수정한다.

- Id: 저장용 고유값. 이미 플레이한 의뢰의 Id는 유지.
- Title / Description: 화면에 보일 이름과 설명.
- Target Scene: 처치가 집계될 씬 경로.
- Enemy Kind: Any / Melee / Ranged.
- Required Kills: 필요 처치 수.
- Reward Gold: 보상 골드.
- Repeatable: 보고 후 다시 수락할 수 있는지.

수락할 때 대상 씬·적 종류·필요 수·보상을 저장한다. 설정을 바꿔도 진행 중인 의뢰의 조건과 보상은 바뀌지 않으며 새 수락부터 반영된다. 반복 여부는 현재 설정을 따른다. 새 의뢰는 고유 Id를 가진 목록 항목을 추가한다.

NpcManager의 Guild Quest Giver를 켠 프로필이 의뢰 화면을 연다. 길드 접수원과 게시판은 같은 프로필을 사용한다. 게시판은 기존 배치 그대로이며 새로운 의뢰를 받을 별도 시설은 없다.

## 저장과 보상

- 수락과 보상 수령 시 즉시 자동 저장.
- 처치 진행은 기존 맵 전환 전·후 자동 저장에 포함.
- 저장 버전 1에 선택 필드를 추가했다. 기존 저장에는 빈 의뢰 목록으로 이어진다.
- 같은 의뢰의 중복 수락·미완료 보고·중복 보상을 차단한다.
- 보상 저장이 실패하면 골드와 의뢰 상태를 되돌려 재시도할 수 있다.
- 금액 범위를 넘는 지급은 거절한다.

## 검증 도구

- WorldRouteAudit.Validate: 전체 맵 연결과 출입구·NPC·획득물 접근점, 길드↔던전 주요 경로 검사.
- GuildQuestCheck.Run / Resume: 실제 무기 피격 처치, 재실행 후 부분 진행, 귀환·보고, 보상 저장 실패/재시도, 중복 보상 방지, 반복 의뢰 검사. 이동은 충돌 검사를 사용하는 MovePlayer로 경로를 따라 진행하며 카메라의 맵 경계와 플레이어 포함 여부도 검사한다.
- InteriorWorldCheck.Run: 기존 11개 맵·22방향 왕복과 대장간 거래, 이동·저장·집 재설치 점검.

로컬 플레이 검사는 별도 프로젝트와 별도 저장 폴더에서 실행한다. 본인 저장 파일을 초기화하지 않는다.

## 동선 측정

현재 11개 씬·출입구 22개, 시작점에서 출입구/NPC/배치 아이템까지 접근점 35곳을 검사했다. 길드에서 던전까지 야외 경로는 51.0유닛, 귀환은 48.3유닛이다. 조작 개선 후 기본 이동 속도 4.5 기준 약 11.3초/10.7초이며 로딩과 건물 안 걷기는 제외한 추정치다. 현재 경로에 막힘이 없어 사용자 맵 배치를 추가로 변경하지 않았다.

실제 전투·의뢰 검사에서는 순간이동만으로 출입을 확인하지 않고 충돌 처리로 경로를 따라 총 220.5유닛을 이동했다. 별도 재실행으로 부분 진행이 유지되는지, 보상 저장이 잠겨 실패했을 때 골드/진행이 복구되는지와 재시도·중복 지급 차단까지 확인했다.
