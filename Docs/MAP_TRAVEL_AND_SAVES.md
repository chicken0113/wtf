# 맵 상태 유지와 자동 저장

## 현재 동작

- 새 게임을 처음 시작할 때 기본 아이템을 포함한 초기 상태를 자동 저장한다.
- 출입구 이동 전에 현재 맵과 플레이어를 저장한다. 목적지의 도착 지점 확인과 복원이 끝나면 도착 상태도 저장한다.
- 다시 실행하면 마지막으로 저장한 맵·위치·소지품으로 이어서 시작한다.
- 저장 대상: 인벤토리 아이템/수량/선택 칸, 골드, 떼어낸 인벤토리 칸과 하트, HP, 처치 수, 낮밤 진행도, 맵별 경작지/물/식재 대상/성장도/재수확 상태, 드롭 아이템의 위치와 크기, 직접 설치한 집, 수확해서 사라진 기존 집.
- 다른 맵에 남겨 둔 성숙한 창고 식물의 인벤토리 용량 효과도 유지하므로 이동 때문에 소지품이 넘쳐 떨어지지 않는다.
- 다른 맵에서 게임 시간이 흐르면, 돌아왔을 때 물을 준 작물은 그 시간만큼 성장한다. 게임을 종료한 시간과 씬 로딩 시간은 성장 시간에 포함하지 않는다.
- 적과 탄환은 현재 시제품의 전투 초기화 규칙을 따른다. 이번 저장 대상에 적 개별 상태는 포함하지 않는다.

## 씬에서 출입구와 도착 지점 배치

1. 기존 집의 위치나 계층을 편집하기 전에 **Tools > Everything Grows > 고급 > 현재 맵 저장 ID 준비**를 실행하고 씬을 저장한다. 각 집에 고유 저장 ID를 부여하며 위치와 외형은 바꾸지 않는다. 씬을 복제한 뒤에도 해당 메뉴를 사용할 수 있다.
2. **Assets/Prefabs/Map/MapArrivalPoint.prefab**을 도착할 씬에 놓는다. `Arrival Id`를 지정하고 실제 플레이어가 설 위치로 이동한다. 같은 씬 안에서는 ID를 중복시키지 않는다.
3. **Assets/Prefabs/Map/MapExit.prefab**을 출발할 씬에 놓는다. Inspector의 `Destination Scene`에 대상 씬 파일을 지정하고, 도착 지점과 같은 `Arrival Id`를 입력한다.
4. `Area Size`로 출입구 영역을 조절한다. 지역 간 이동에는 `Require Interact`를 꺼서 닿으면 이동하도록 한다. E가 필요한 문은 건물 실내 출입에만 사용한다. 도착 직후에는 1초간 자동 이동을 막는다.
5. Inspector에 Build Settings 경고가 나타나면 **Enable destination in Build Settings**를 누른다. 출발 씬도 Build Settings에 등록되어 있어야 하며 Tools > Everything Grows > 고급 > 현재 씬 빌드 등록로 등록할 수 있다. 대상 씬에는 기본 데이터가 설정된 FarmGame과 활성화된 도착 지점이 필요하다.
6. 왕복 연결은 반대 방향 출입구와 도착 지점을 별도로 배치한다. GameObject > Everything Grows 메뉴에서도 두 오브젝트를 생성할 수 있다.

출입구와 도착 지점은 Scene에서 초록 영역·청록 표시로 보인다. 플레이 중 실내 출입용 문에만 E 이동 안내가 표시되며 지역 이동에는 E가 필요하지 않다. 실제 문의 외형은 출입구에 SpriteRenderer나 장식 오브젝트를 붙여 구성할 수 있다.

## 저장 파일과 실패 처리

- 기본 단일 자동 저장 슬롯: `Application.persistentDataPath/wtf/wtf-autosave.json`.
- 현재 Windows 프로젝트 설정의 경로는 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/EverythingGrows/wtf/`이다. 원격 Git 저장소가 아닌 로컬 플레이 데이터다.
- 임시 파일에 기록한 후 교체하며 이전 파일은 `.bak`으로 보관한다. 기본 파일의 JSON이 손상됐으면 백업을 읽는다.
- 저장된 아이템 참조가 사라졌거나 복원할 수 없는 경우 기존 파일을 새 게임으로 덮어쓰지 않는다. 저장/이동 오류를 화면에 표시한다.
- 대상 씬이 Build Settings에 없으면 이동을 시작하지 않는다. 도착 지점이 없거나 중복됐거나 대상 씬에 FarmGame이 없으면 저장한 출발 맵으로 돌아온다.
- 씬 파일 경로는 저장 맵의 키다. 저장을 이어 쓸 때 씬 경로와 Map Object ID를 유지한다.
- 아이템은 GUID 기반 `Assets/Resources/SaveItemCatalog.asset`으로 참조한다. 에디터가 PlantDefinition 변경 시 갱신하며 **Tools > Everything Grows > 고급 > 저장용 아이템 목록 갱신**로 직접 갱신할 수도 있다.

## 집에서 시간 보내기 연동

`GameSession.SaveAfterHouseTime(farm)`을 행동 완료 시 호출하도록 연결 지점을 제공한다. 집에서 시간을 보내는 행동 자체는 아직 구현하지 않았으며, 이번 작업에서 수면·날짜 규칙을 새로 추가하지 않는다.

## 검증

별도 임시 Unity 프로젝트와 테스트 전용 저장 폴더에서 실제 Play 모드로 맵 왕복, 잘못된 도착 지점의 원복, 소지품/HP/골드 유지, 밭과 성장도, 부재 시간 성장, 드롭 크기, 설치한 집, 수확한 원래 집의 제거 상태, 재실행 및 백업 복원을 검사한다. 사용자 플레이 저장 파일은 검증에 사용하지 않는다.


## 두 종류의 입출구

| 프리팹 | 색상 | 동작 |
| --- | --- | --- |
| `Assets/Prefabs/Map/MapDoorExit.prefab` | 청록색 문틀 | 건물 실내 출입: 영역 안에서 발판을 가리키고 우클릭해 이동 |
| `Assets/Prefabs/Map/MapBoundaryExit.prefab` | 주황색 바닥과 흰 화살표 | 지역 간 이동: 플레이어 몸이 닿으면 자동 이동 |

Hierarchy의 `GameObject > Everything Grows > Door Exit (E)` 또는 `Boundary Exit (Touch)`로도 배치할 수 있습니다. 기존 `MapExit.prefab`은 장식 없는 기본 영역으로 유지합니다.

MapExit Inspector의 **Activation**에서 Door / Boundary를 선택합니다. 새 프리팹은 모드에 따라 색도 변경됩니다. **Destination Scene**, **Arrival Id**는 이전과 동일하게 설정하며, **Area Size**는 이동 판정 크기입니다. 장식의 크기와 위치는 자식 오브젝트에서 조절합니다. Scene의 Gizmos 색도 두 모드를 구분합니다.

자동 통로는 캐릭터 중심이 아니라 Player Radius를 포함한 몸 판정을 사용합니다. 저장 복원이나 맵 도착 시 자동 통로와 겹치면 한 번 밖으로 나간 후 다시 닿아야 활성화됩니다. 도착 후 짧은 이동 유예도 유지해 즉시 왕복되는 현상을 방지합니다.

지역 사이의 청록색 상호작용 문은 제거했습니다. 주황색 통로는 농장 `(9, 0)`과 전투 맵 `(-10, 2.5)`에서 마을로 이어집니다. 각 씬의 `Touch Map Connection` 그룹에서 이동·삭제할 수 있습니다. 자동 통로 도착 지점은 문형 출입구와 별도로 구성합니다.


## 현재 월드 연결

농장과 던전은 주황색 접촉 통로로 마을과 왕복하며 서로 직접 이어지는 자동 통로도 있습니다. 파란 상호작용 문은 Town ↔ GeneralStore 실내 출입에 남겨 둡니다. Town과 GeneralStore 씬을 추가했고, 전체 배치와 NPC 설정은 [WORLD_FRAMEWORK.md](WORLD_FRAMEWORK.md)를 참고하세요.


## 2026-10-23 저장 점검 결과

현재 코드와 씬을 복사한 격리 Unity 프로젝트 및 별도 테스트 저장으로 확인했다. 실제 사용자 저장과 원본 씬은 검사에 사용하지 않았다.

| 확인 항목 | 결과 |
| --- | --- |
| 월드 왕복 후 작물·인벤토리·골드·드롭 유지 | 통과 — 기존 InteriorWorldCheck, 13개 맵 구성/24개 방향 이동 |
| 집 수확·다른 위치에 설치·내부 저장 후 재실행 | 통과 — 옮긴 집의 문으로 복귀, 인벤토리·설치 집 유지 |
| 성장 25%에서 저장 후 새 FarmGame에 복원 | 통과 — 아이템 ID·진행도·물 준 상태·소지 수량·골드 유지 |
| 복원한 작물을 다 키워 저장 후 재복원 | 통과 — 성숙 상태 유지, 아이템 수량 중복 없음 |
| 주 저장 파일 손상 시 백업 복구 | 통과 — 별도 저장의 주 파일만 손상시켜 이전 정상 성장 상태 복원 |
| 탑 저장 후 재실행·계단 왕복 | 통과 — 클리어/처치 상태, 드롭·장비·골드·체력 유지 |

게임 코드나 저장 형식을 수정할 문제는 발견되지 않았다. 성장 검사는 기존 CaptureMap/Save/Bind를 직접 사용하는 임시 검사로 수행했고, 맵/집 및 탑 재접속은 기존 InteriorWorldCheck.Run/Resume와 TowerDungeonCheck.Resume를 재사용했다. 앱을 닫은 현실 시간만큼 성장하는 기능을 추가한 작업은 아니다.

## 인벤토리 슬롯 위치 저장

인벤토리 이동을 지원하며 버전 1에 `PlayerSave.inventoryUsesSlots`와 `ItemStackSave.slot`을 추가했다. 새 저장은 점유 칸만 번호와 함께 저장하여 중간 빈칸이 유지된다. 이전 저장은 목록 순서대로 배치하며 아이템 ID/수량을 보존한다. 중복·음수 번호는 정상 인벤토리 교체 전에 거부한다. Unity에서 용량을 줄인 경우 범위 밖 아이템은 삭제하지 않고 기존 바닥 드롭으로 보존한다. 선택한 핫바 번호는 현재 핫바 범위로 제한한다. 설정 위치와 조작은 FOUNDATION_CONTROLS.md를 참고한다.
